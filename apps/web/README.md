# apps/web — pilot UI (M7 minimum + Design Studio)

The pilot workflow in 7 steps, over `/api/v1` only:
1. **Login** — Supabase Auth (email + password, publishable key); in LOCAL mode, a demo token.
2. **Project** — the organization; create or open a project with its client; the project team.
3. **Room** — a rectangular kitchen: width along wall A, depth, height, wall thickness; no openings.
4. **Design Studio** — the primary cabinet-design experience (Phase D6): a Cabinet Library, a live 3D viewport, plan/elevation/BOM, and a Properties panel to add a cabinet, change its dimensions and front (1/2 shutters, overlay/inset), save and remove it. Replaces the earlier "Base cabinets" table and "Preview" screens as the primary editing surface; their code remains (`screens/Layout.tsx`, `screens/Preview.tsx`) and is reused by the Design Studio (version selection, plan/elevation drawing), not navigated to directly. See `docs/architecture/DESIGN-STUDIO-D1-D6.md`.
5. **Validation** — BLOCKERs, warnings and passed checks; the APPROVAL run; submit → approve → lock.
6. **Outputs** — BOM, BOQ, Pricing, Quotation and execution drawings, generated by the API's engines.
7. **Issue** — the existing issue workflow: quotation (Sales, with a hand-over code from Costing) and drawings (Design Head). The issued drawing PDFs and the quotation PDF (sealed with the quotation) can be downloaded.

**No business calculation happens here.** ESLint forbids importing engines, persistence, storage or database code, with one narrow exception: `@lintel/cabinet-engine`, a pure typed domain-model/mapping package (no engine, persistence, react or rendering code of its own) the Design Studio uses instead of duplicating the cabinet domain model in the UI. All geometry, validation, quantities, prices and totals are shown exactly as the API returns them; Three.js only places and colours boxes the API already resolved.

| Command | Purpose |
|---|---|
| `pnpm pilot:demo` | LOCAL: API + UI + rehearsal data. Open http://127.0.0.1:5173 and paste a token from `.pilot/tokens/` |
| `pnpm web:dev` | UI only. Proxies `/api` to `LINTEL_API_URL` (default http://127.0.0.1:3000) |
| `pnpm web:build` | Static build (`apps/web/dist`) |
| `pnpm --filter @lintel/web api:types` | Regenerate `src/api/schema.d.ts` from `apps/api/openapi/openapi.json` |
| `pnpm pilot:ui-e2e` | Browser walkthrough of all 7 steps against a running `pilot:demo` (Playwright + Chromium) |

| Variable (build time) | Meaning |
|---|---|
| `VITE_APP_ENV=local` | LOCAL demo sign-in (paste a token). Otherwise Supabase Auth |
| `VITE_SUPABASE_URL`, `VITE_SUPABASE_PUBLISHABLE_KEY` | The Supabase project URL and its **publishable** key. Never a secret key |
| `LINTEL_API_URL`, `WEB_PORT` | Dev / preview server: the API to proxy, and the port |
